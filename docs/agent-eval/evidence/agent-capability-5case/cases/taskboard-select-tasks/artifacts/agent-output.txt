## 5. 实现方案（分析结论，未执行）

签名必须保持 `tasks` 为位置参数、`status` 与 `query` 为**关键字专用**（已有测试用 `select_tasks(tasks, status="open", query="api")` 调用，且被调用方不得破坏）。

按现有函数风格实现：

```python
def select_tasks(tasks, *, status=None, query=""):
    rows = list(tasks)
    lowered_query = query.lower() if query else None
    lowered_status = status.lower() if status is not None else None
    return [
        task for task in rows
        if (lowered_status is None or str(task.get("status", "")).lower() == lowered_status)
        and (lowered_query is None or lowered_query in str(task.get("title", "")).lower())
    ]
```

各条要求与实现手段的对应：

| 需求 | 手段 |
| --- | --- |
| status 忽略大小写 | 双侧 `.lower()` 比较（不能复用 `filter_by_status`，它目前是大小写敏感的 `==`） |
| 标题关键字忽略大小写 | 双侧 `.lower()` 后 `in` 判断（不能复用 `search_tasks`，它目前是大小写敏感的） |
| 两条件取交集 | 单个推导式的两个 `and` 条件 |
| `status=None` 不启用筛选 | `lowered_status is None` 短路 |
| 空 `query` 不启用筛选 | `if query` 判断，falsy 时置 `None` |
| 无 `title` 不误匹配 | `str(task.get("title", ""))`；空串不可能包含非空 query |
| 保留输入顺序 | 推导式顺序遍历 `rows` |
| 不修改输入 | 不调用 `sort`/`in` mutating；可复用既有 `rows = list(tasks)` 风格 |

`tests/test_select_tasks.py` 现有断言与目标的对照（说明扩测要覆盖的缺口）：

- ✅ `select_tasks(tasks, status="open", query="api") == [1, 3]`（交集 + 双侧忽略大小写）
- ✅ `select_tasks(tasks, query="API") == [1, 2, 3]`（只 query；id=4 缺 title 被正确排除）
- ✅ `select_tasks(tasks, status="missing") == []`（无匹配）
- ✅ `tasks == original`（输入未被修改）
- ⬜ 缺口：单一 `status` 参数（`query=""`）的返回、`tasks` 为一次性可迭代对象（生成器）时的行为、`status=None, query=""` 返回全部

## 6. 风险与建议

1. **“新增函数 / 新建测试文件 / 包导出”三项在仓库里其实已存在**。若按“新写”处理，可能无意重复定义或改动 `__init__.py`，而 `cases/*.json` 的 `allowed_files`/`required_changed_files`（如 `taskboard/tasks.py`、`tests/test_select_tasks.py`）对可控范围有约束。建议只替换 `tasks.py` 中那个 `raise NotImplementedError` 函数体，`__init__.py` 不动。
2. **不要直接复用 `filter_by_status` 与 `search_tasks`**：这两个函数当前都是**大小写敏感**的（`cases/taskboard-status-filter.json` 和 `taskboard-title-search.json` 正是要求修它们大小的独立用例）。`select_tasks` 里若复用它们会直接违反“忽略大小写”。
3. **边界语义需按测试推定的约定**：`query` 为 `None` 时应与空串等价处理，否则会出现 `None.lower()` / `in None` 的 `TypeError`；`status` 与任务的 `status` 都用 `str(...)` 或 `is not None` 分支防御，避免 `{"id": 4, "status": None}` 场景崩溃。
4. **一次性可迭代对象**：签名标注为 `Iterable`，若外部传入生成器，必须在函数内只消费一次（用 `list(tasks)`），且返回列表不得影响调用方后续行为。
5. **评测层面的隐性检查**：`tests/` 中的可见测试只是基线，`cases/*.json` 里 `oracle_tests` 是仓库外的独立校验。除可见断言外，建议按上述表格逐条自查（尤其“缺 title 不误匹配”和“保留输入顺序”），不要只对齐现有 4 条断言就收尾。
6. 本轮为只读分析，`git status` 干净（`## main`），未产生任何文件改动、提交或 PR；`main@2d542e0（eval baseline）`。
