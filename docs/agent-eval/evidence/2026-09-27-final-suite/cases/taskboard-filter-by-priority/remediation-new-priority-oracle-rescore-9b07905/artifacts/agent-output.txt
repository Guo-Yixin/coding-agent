# filter_by_priority 技术方案

## 1. 需求理解

在 `taskboard` 包中新增并发导出 `filter_by_priority(tasks, priorities=None)`，语义如下：

| 需求点 | 目标行为 |
| --- | --- |
| `priorities=None` | 不做过滤，返回全部任务（原顺序） |
| 传字符串 | 视为单元素筛选集合，例如 `"high"` 只筛 high 类 |
| 传字符串 Iterable | 视为多元素集合，例如 `["medium", "backlog"]` |
| 大小写忽略 | 任务值 `"HIGH"` 与筛选值 `"high"` 视为同一级别 |
| 别名等价 | `urgent` → `high`；`backlog` → `low`（双向归一后比较） |
| 缺失/null 归 unknown | `task` 无 `priority` 键或值为 `None` 时，归一为 `unknown`；筛选值写 `"unknown"` 可命中这类任务 |
| 顺序保持 | 结果按输入顺序输出，类似 `list` / 生成器等可迭代输入也向下转换为列表 |
| 不修改输入 | 只做只读遍历与生成新列表，不写入任务字典 |

与既有实现的关系：
- **必须复用 `urgent/backlog` 别名语义**。`tests/test_baseline.py::test_priority_sort_orders_known_priorities` 与 `sort_by_priority` 已确认需要在排序中区分 urgent/backlog：`test_priority_sort_keeps_equal_and_unknown_priorities_stable` 期望 `[2(urgent), 4(high), 5(high), 1(low), 3(backlog)]`，即排序侧 `urgent` 与 `high` **不同组**、`backlog` 与 `low` **不同组**。
- 因此筛选侧的别名等价不能改动 `sort_by_priority`，应作为**筛选专用的归一化**局部实现；`sort_by_priority` 保持现状不动（同时它是另一 case 的必改文件，和本任务的 allowed_files 重叠，需避免相互影响）。
- `search_tasks` 的任务标题比较实际是大小写敏感的（`query in title`，小写查询匹配大写标题会失败），所以大小写忽略的实现方式要参考 `filter_by_status` 的做法思路 —— 使用 `str(...).lower()` 归一，但**不能照搬 `filter_by_status` 的相等比较**，因为它对 `None` 值与缺失键的处理不符合本需求（一致地把缺失和 null 归到 `unknown`）。

**核心逻辑伪代码（约 7 行，示意用）**

```
targets = None if priorities is None else set→{normalize(p) for p in 对 goals 的展开}
rows = list(tasks)
若 targets 为 None：返回 rows
返回 [t for t in rows if normalize(t.get("priority")) in targets]
```

其中"对 `goals`（即 `priorities`）的展开"需先判断入参是单个字符串还是 Iterable 字符串：字符串不再按字符迭代。

| 返回 | `list[Task]`，元素为原字典对象本身（浅拷贝式结果，不改写元素） |

**归一化规则表（模块内私有常量/辅助逻辑，不在包外导出）**

| 输入侧写法（忽略大小写） | 归一结果 |
| --- | --- |
| 键缺失 / `None` / 空串或仅空白 | `unknown` |
| `high` | `high` |
| `urgent` | `high` |
| `medium` | `medium` |
| `low` | `low` |
| `backlog` | `low` |
| 其它字符串（如 `later`） | 保持写法的"已小写化"形式，用于精确相等比较 |

**核心逻辑伪代码（约 7 行，示意用）**

```
targets = None if priorities is None else set→{normalize(p) for p in 对 goals 的展开}
rows = list(tasks)
若 targets 为 None：返回 rows
返回 [t for t in rows if normalize(t.get("priority")) in targets]
```

其中"对 `goals`（即 `priorities`）的展开"需先判断入参是单个字符串还是 Iterable 字符串：字符串不再按字符迭代。

**需要用户确认的事项**

- **Q1（空白优先级）**：`task["priority"] = ""` 或 `"   "` 是否与 `None`/键缺失一样归入 `unknown`？本方案默认为"归 `unknown`"，因为需求把"缺失或 null"归 unknown 的意图是把无有效优先级统一归类；若不希望把空串计入，将改为只对缺失/`None` 生效，测试断言随之调整。
- **Q2（别名规范化的方向对称性）**：`urgent` 等价 `high` 应当是**双向**的（筛选值写 `urgent` 也能命中原生 `high` 任务），本方案按双向实现；若只要求单向（任务侧 `urgent` 可被 `high` 命中、筛选侧 `urgent` 不覆盖 `high`），语义会变窄。

- **Q4（对比范围）**：需求描述是"字符串 Iterable"，是否含 `set`/`tuple`/`generator`/`dict_keys` 等所有常见可迭代对象？本方案全部支持并把集合视为无序输入，结果只保证遵循**任务输入**顺序，不承诺筛选集合的顺序语义。
