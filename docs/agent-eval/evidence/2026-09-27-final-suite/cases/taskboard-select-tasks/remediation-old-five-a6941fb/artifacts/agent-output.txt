def select_tasks(
    tasks: Iterable[Task],
    *,
    status: str | None = None,
    query: str = "",

### 3.3 行为契约表
| 输入组合 | 判定方式 | 示例结果（基于 `tests/test_select_tasks.py` 数据） |
| --- | --- | --- |
| `status=None, query=""` | 不做任何筛选，返回全部任务的新列表 | 4 条全部返回 |
| `status="open", query=""` | 仅状态匹配（忽略大小写 + 需要归一化） | 命中 id 1、3、4 |
| `status=None, query="API"` | 仅标题包含（忽略大小写） | 命中 id 1、2、3 |
| `status="open", query="api"` | 两个条件同时满足（交集） | 命中 id 1、3 |

| `query="api"` 且任务缺 `title` | 视为不匹配 | id 4 被排除 |

### 3.4 归一化规则建议
| 场景 | 处理 |
| --- | --- |
| `status` 与任务 `status` 都可为 `None` / 缺失 | `status=None` 直接跳过该条件；条件启用时，任务侧缺失 `status` 视为不匹配（不用 `"None"` 之类假值参与比较） |
| 任务 `status` 非字符串 | 与兄弟函数保持一致的宽松策略：转 `str()` 后比较，避免 `TypeError` |
| `query` 为 `""` | 跳过标题条件；同时建议把仅含空白的 `query` 也按「未启用」处理（见 6.1 待确认项） |
| 任务 `title` 缺失或为 `None` | `str(task.get("title") or "")`，保证不会因为 `None` 变成 `"none"` 而误匹配 |
| 多语言大小写 | 使用 `str.lower()`；不引入 `casefold()`，以与现有筛选方案保持一致 |

- 期望语义与 `filter_by_status`（大小写不敏感版）、`search_tasks`（大小写不敏感版）对齐，即 `select_tasks` 等价于两者的交集。

## 3. 数据结构、接口或页面变化

### 3.1 无数据结构变更
沿用现有类型别名 `Task = dict[str, Any]`，不新增模型、不新增依赖、不改 `pyproject.toml`。

### 3.2 接口定义（唯一新增/变化的公开接口）
```python
def select_tasks(
    tasks: Iterable[Task],
    *,
    status: str | None = None,
    query: str = "",
) -> list[Task]: ...
```

### 3.3 行为契约表
| 输入组合 | 判定方式 | 示例结果（基于 `tests/test_select_tasks.py` 数据） |
| --- | --- | --- |
| `status=None, query=""` | 不做任何筛选，返回全部任务的新列表 | 4 条全部返回 |
| `status="open", query=""` | 仅状态匹配（忽略大小写 + 需要归一化） | 命中 id 1、3、4 |
| `status=None, query="API"` | 仅标题包含（忽略大小写） | 命中 id 1、2、3 |
| `status="open", query="api"` | 两个条件同时满足（交集） | 命中 id 1、3 |
| `status="missing"` | 无匹配返回空列表，不是 `None` | `[]` |
| `query="api"` 且任务缺 `title` | 视为不匹配 | id 4 被排除 |

### 3.4 归一化规则建议
| 场景 | 处理 |
| --- | --- |
| `status` 与任务 `status` 都可为 `None` / 缺失 | `status=None` 直接跳过该条件；条件启用时，任务侧缺失 `status` 视为不匹配（不用 `"None"` 之类假值参与比较） |
| 任务 `status` 非字符串 | 与兄弟函数保持一致的宽松策略：转 `str()` 后比较，避免 `TypeError` |
| `query` 为 `""` | 跳过标题条件；同时建议把仅含空白的 `query` 也按「未启用」处理（见 6.1 待确认项） |
| 任务 `title` 缺失或为 `None` | `str(task.get("title") or "")`，保证不会因为 `None` 变成 `"none"` 而误匹配 |
| 多语言大小写 | 使用 `str.lower()`；不引入 `casefold()`，以与现有筛选方案保持一致 |

### 3.5 与兄弟函数的关系
- 期望语义与 `filter_by_status`（大小写不敏感版）、`search_tasks`（大小写不敏感版）对齐，即 `select_tasks` 等价于两者的交集。
- 但**不把 `select_tasks` 实现为对这两个函数的直接链式调用**：它们当前未做大小写归一化，直接复用会让新功能依赖本次改动范围外的修复。若后续这两个函数在同一 commit 中一并修复，可在 review 阶段讨论是否改为复用，但本方案默认自洽实现。
