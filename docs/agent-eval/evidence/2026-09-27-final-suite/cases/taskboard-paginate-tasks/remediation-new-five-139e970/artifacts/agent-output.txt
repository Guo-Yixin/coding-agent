# paginate_tasks 技术方案（只读分析，未改动任何文件）

## 1. 需求理解

在 `taskboard` 包中新增公开函数 `paginate_tasks(tasks, *, page, page_size)`，语义如下：

| 序号 | 要求 | 判定方式 |
| --- | --- | --- |
| 1 | `page` 从 1 开始计数 | `page=1` 返回第一段，`page=2` 返回第二段 |
| 2 | `page`、`page_size` 必须是正整数 | 1、2、3… 合法；0、负数不合法 |
| 3 | `bool` 不算整数 | `True`/`False` 必须被拒绝（`isinstance(True, int)` 为真，需显式排除） |
| 4 | 非法入参抛 `ValueError` | 不是 `TypeError`，也不是静默裁剪；空输入也要先校验参数 |
| 5 | 超出末页返回空列表 | `page * page_size` 超过总数时返回 `[]`，不抛异常 |
| 6 | 接受一次性 `Iterable` | 生成器、`map`/`filter` 对象只遍历一次也能正确分页 |
| 7 | 保留输入顺序 | 结果相对顺序与输入一致，不做排序 |
| 8 | 不修改输入 | 不调用 `.sort()`、不 `pop/remove`、不就地改动原列表 |
| 9 | 通过包导出 | 既能 `from taskboard import paginate_tasks`，也能 `from taskboard.tasks import paginate_tasks` |
| 10 | 扩展测试文件 | 只在 `tests/test_paginate_tasks.py` 中追加用例 |

核心实现逻辑（伪代码，约 5 行）：

```python
def 校验(value):  # bool 先排除，再判断 int 且 > 0，否则 ValueError
def paginate_tasks(tasks, *, page, page_size):
    校验(page); 校验(page_size)
    start = (page - 1) * page_size
    return list(islice(tasks, start, start + page_size))  # 或物化后切片
```

关于“一次性 Iterable”有两种等效做法，方案建议任选其一并在测试中固定行为：

| 做法 | 特点 | 风险 |
| --- | --- | --- |
| A. 完全物化：`rows = list(tasks)` 后切片 | 与同文件其它函数风格一致，超末页自然得到 `[]`；支持任意 `Iterable` | 大输入内存占用为 O(n) |
| B. 惰性切片：`itertools.islice(tasks, start, start + page_size)` | 只遍历到需要的偏移处；也能正确处理生成器 | 代码略隐晦，需注意 `islice` 会推进迭代器（输入被消费属预期，非“修改输入”） |

推荐 A，理由是维持仓库一致性，避免评审时对 `islice` 语义产生分歧；两者都必须保证：入参校验**在**消费 `tasks` 之前完成，这样 `paginate_tasks([], page=0, page_size=2)` 才能按要求抛 `ValueError` 而不是先返回 `[]`。

## 6. 风险点和需要用户确认的事项

| 风险 | 说明 | 处置建议 |
| --- | --- | --- |
| `bool` 判断易被漏掉 | `isinstance(True, int)` 为真，只判 `isinstance(x, int)` 会让 `page=True` 通过 | 先 `isinstance(value, bool)` → `raise ValueError`，再判 `int` 与 `> 0` |
| 异常类型必须是 `ValueError` | `True`/`1.5` 这类若用类型注解或不加判断，可能抛 `TypeError` 或静默通过 | 显式校验并统一抛 `ValueError`；测试用 `pytest.raises(ValueError)` 锁死 |

**1. `taskboard/tasks.py`（+23 行）**

新增私有校验辅助函数，用于集中处理“bool 不算整数 + 必须是正整数”：

```python
def _validate_positive_int(value: Any, name: str) -> int:
    """Return value as a positive int, rejecting bools and non-integers."""
    if isinstance(value, bool) or not isinstance(value, int) or value <= 0:
        raise ValueError(f"{name} must be a positive integer, got {value!r}")
    return value
```

新增公开函数（放在 `sort_by_priority` 之后，沿用同文件“物化输入 + 返回新列表”的风格）：

```python
def paginate_tasks(tasks: Iterable[Task], *, page: int, page_size: int) -> list[Task]:
    page = _validate_positive_int(page, "page")
    page_size = _validate_positive_int(page_size, "page_size")
    rows = list(tasks)
    start = (page - 1) * page_size
    return rows[start : start + page_size]
```

关键点：先校验参数再消费 `tasks`，因此空输入配非法参数也会抛 `ValueError`；`bool` 在 `isinstance(value, bool)` 处先被拦下；越界切片自然返回 `[]`；不调用任何就地修改方法，返回元素是原对象引用。
