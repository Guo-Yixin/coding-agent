# taskboard 新增 `count_by_status(tasks)` 技术方案

## 1. 需求理解

在小型 Python 库 `taskboard` 中新增一个公开统计函数 `count_by_status(tasks)`，用于按任务状态分组计数。已通过 `hybrid_code_search` 与文件读取确认：`tests/test_count_by_status.py` 已经存在（属于评测用例的验证文件），但 `taskboard` 包尚未导出该函数，当前 `python -m pytest -q` 会在收集阶段直接报 `ImportError: cannot import name 'count_by_status'`，导致整套测试中断。

要求拆解如下：

| 编号 | 要求 | 判定要点 |
| --- | --- | --- |
| R1 | 按 `status` 分组计数 | 返回「归一化状态 → 数量」的映射 |
| R2 | 去除首尾空格 | `"  OPEN "` 与 `"open"` 归为同一组 |
| R3 | 忽略大小写 | `"Open"` 与 `"open"` 归为同一组 |
| R4 | 缺失状态 / `null` / 纯空白归入 `unknown` | 无 `status` 键、`status is None`、`status == "   "` 三种情况都是 `unknown` |
| R5 | 键按状态首次出现顺序排列 | Python `dict` 插入序即结果顺序；`unknown` 的位置由首次出现决定，不强制排在末尾 |
| R6 | 输入不被修改 | 不写入、不归一化回原 `task`，只读访问 |
| R7 | 通过 `taskboard` 包导出 | 既能 `from taskboard import count_by_status`，也能 `from taskboard.tasks import count_by_status` |
| R8 | 扩展 `tests/test_count_by_status.py` | 保留现有 2 个用例，补充边界用例 |
| R9 | 只改 3 个文件 | `taskboard/tasks.py`、`taskboard/__init__.py`、`tests/test_count_by_status.py` |

## 2. 涉及模块和需要阅读的文件

| 文件 | 作用 | 需要关注的点 |
| --- | --- | --- |
| `taskboard/tasks.py` | 功能实现处 | 已有 `Task = dict[str, Any]` 类型别名；现有函数统一先 `rows = list(tasks)` 物化输入 |
| `taskboard/__init__.py` | 包级再导出 | 现有 `from taskboard.tasks import ...` 与 `__all__` 列表需同步扩展 |
| `tests/test_count_by_status.py` | 目标测试文件 | 已有 2 个用例，锁定 `{"open": 2, "done": 1, "unknown": 2}` 与 `{}` |
| `pyproject.toml` | 测试配置 | `testpaths = ["tests"]`、`addopts = "-ra"`，无额外 pytest 插件 |
| `tests/test_filter_by_status.py`、`tests/test_baseline.py`、`tests/test_search_tasks.py` | 风格与回归参照 | 断言风格为 `assert count == {...}`，并有「构造 `original` 副本对比」的不变性验证写法 |

已确认仓库基线与测试方式：`git log` 最新提交为 `3d2161d eval baseline`；测试命令为仓库根下的 `python -m pytest -q`。

## 3. 数据结构、接口或页面变化

**新增接口**

- 签名：`count_by_status(tasks: Iterable[Task]) -> dict[str, int]`
- 语义：输入为任务字典的可迭代对象，输出为按首次出现顺序排列的「归一化状态 → 计数」字典。
- 归一化规则：
  - `status` 存在且 `str(...)` 去首尾空白后非空 → 小写化作为键；
  - 键缺失、值为 `None`、值去空白后为空字符串 → 键为 `"unknown"`。
- 无输入、空输入一律返回空字典 `{}`（不预置 `"unknown": 0`）。
- `"unknown"` 不是一个保留位次，它和普通状态一样按首次出现位置插入，因此 `{"status": "OPEN"}` 先于 `{"id": 4}` 出现时结果为 `{"open": 1, "unknown": 1}`；若缺失任务最先出现则 `unknown` 排在首位。

**模块导出变化**

- `taskboard/__init__.py` 的 `__all__` 由 `["filter_by_status", "search_tasks", "sort_by_priority"]` 变为 `["count_by_status", "filter_by_status", "search_tasks", "sort_by_priority"]`（或与其他成员保持一致地追加在末尾，实际顺序不影响可导入性）。

**内部结构（不新增模块、不新增依赖）**

- 复用现有 `Task` 别名；返回值使用 `dict[str, int]`，不使用 `collections.Counter`（`Counter` 也能保序，但直接使用普通 `dict` 更能显式表达「首次出现顺序」这一契约，也避免额外 import）。
- 不修改 `filter_by_status`、`search_tasks`、`sort_by_priority` 的行为。

核心流程可用如下 6 行伪代码概括：

```
result = {}
for task in tasks:
    raw = task.get("status") if isinstance(task, Mapping) else None
    key = str(raw).strip().lower() if raw is not None else ""
    key = key or "unknown"
    result[key] = result.get(key, 0) + 1
return result
```

> 注：`dict.get("status")` 对「缺失键」和「显式 `None`」返回一致结果，天然覆盖 R4 中的两种情形；`task` 若不是映射类型（如误传字符串），按「缺失状态」处理同样落到 `unknown`，作为防御性行为待确认（见第 6 节 Q2）。
