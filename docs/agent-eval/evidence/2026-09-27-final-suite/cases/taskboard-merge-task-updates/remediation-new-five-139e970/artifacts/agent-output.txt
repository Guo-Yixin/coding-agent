# merge_task_updates 技术方案

## 1. 需求理解

在 `taskboard` 这个纯 Python 包中，新增一个纯函数 `merge_task_updates(tasks, task_id, updates)`，用于"只更新一条任务"的不可变合并操作。语义要点：

| 要求 | 具体含义 |
| --- | --- |
| 返回新列表 | 不得返回传入的同一个列表对象，也不得原地修改 |
| 只合并匹配 id 的一条 | 按 `task.get("id") == task_id` 定位；只替换这一条 |
| 目标任务字典需复制 | 结果中该位置是一个新 `dict`，原任务对象保持原样 |
| 不改动输入 | 输入列表与其中每个字典（含未匹配项）都不被修改 |
| 禁止改 id | 若 `updates` 里的 `id` 与 `task_id` 不同，抛 `ValueError` |
| 找不到 task_id | 抛 `KeyError` |
| 其余任务顺序不变 | 保序的浅拷贝替换 |

仓库侧约束：这是一个评测靶场仓库（`cases/` + `README.md` 说明"每个 case 固定 commit，评测方可能运行额外 oracle 检查"），所以实现要按契约严格写，不能只满足可见断言。

**新增函数签名**（放在 `taskboard/tasks.py` 现有函数之后）：

    tasks: Iterable[Task], task_id: Any, updates: Mapping[str, Any]

**契约明细**：

| 场景 | 行为 |

| `updates` 不含 `id` | 合法；合并后 `id` 仍等于 `task_id` |
| 命中项本身无 `id` 字段 | 不视为命中 |
| 多次出现同一 id | 只处理第一个命中项，其余保持原样（"只合并一条"） |
| 无命中 / 输入为空 | 抛 `KeyError` |
| `tasks` 传入非 list 可迭代对象 | 允许（与现有函数一致，先物化为列表） |
