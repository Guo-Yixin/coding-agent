# 视觉方向（参照物冻结）

> 本文件是**冻结过的决定**，不是讨论稿。改它需要走「先改文档再改代码」的流程。
> 冻结日期：本次重构阶段一

## 1. 一句话定位

一个**长时间使用的开发工作台**：信息密度高、需要一眼分清"哪里是导航、哪里是内容、哪里是操作"，安静、克制、不需要用户去适应它。

关键词：**中性、密实、层级分明**。不是"漂亮"，是"耐用"。

## 2. 参照物

对照截图见 `reference/candidates/`。**主参照决定整体调性，辅参照只取指定特征。**

### 主参照：Cursor（`reference/candidates/cursor-1440.png`）

同类产品的成熟形态——三栏（任务列表 / 对话 / 文档）+ 待办清单，与我们的产品形态几乎同构。

**要它的什么：**
- 三栏之间的**分工与对比关系**：侧栏最弱、对话居中、内容最强
- 待办清单的视觉形式：复选框 + 单行文本 + 右侧元信息（时间/耗时）
- **中性灰承担 95% 的界面，彩色只用于状态**（它整屏只有 Build 按钮一处强色）
- 输入区用**细边框**而不是重阴影与内容区做区分
- 运行轨迹/时间这类元信息用小字号、弱色，贴着主内容而不是另外起一行

**不要它的什么：**
- 桌面应用的窗口装饰（标题栏、红绿灯按钮、窗口阴影）—— 我们是网页
- 右侧的代码编辑器区域 —— 我们暂不做编辑器
- 促销横幅、cookie 弹窗等非产品元素
- 它偏冷的背景底（我们用 `--c-bg-subtle` 的更中性的 `#f7f8f8`）

### 辅参照：Linear（`reference/candidates/linear-1440.png`）

**只取这三样：**
1. **灰阶层级**：背景 / 侧栏 / 内容 / 浮层 四层必须一眼分得开
2. **1px 细边框代替阴影** —— 阴影只留给真正浮起的元素（下拉、弹窗）
3. **状态徽标的克制**：小、圆角胶囊、低饱和底色

**明确不取：**
- 深色主题 —— 我们保持浅色
- 它的品牌紫/蓝强调色 —— 我们沿用 `#1f7667`（见 DESIGN.md 说明为什么）
- 它列表的行高与字号 —— 它比我们要更紧凑，我们的正文用 13px 而不是 12px

### 明确不参照

- **Dribbble / Behance 概念稿**：圆角 24px、无 hover 态、无空态、对比度普遍不足。只能取局部灵感，不能作为界面参照。
- **任何营销落地页**：它们是"看一眼就走"的页面，我们是"一天开八小时"的工具。密度要求相反。

## 3. 目标调性（可核对）

| 维度 | 目标 | 反面 |
|---|---|---|
| 灰阶 | 4 层以内（bg / subtle / border / text 各司其职） | 十几种"差不多的白" |
| 彩色 | ≤5 种，且**只用于状态与主操作** | 彩色做装饰 |
| 边框 | 1px，颜色浅 | 到处都是阴影 |
| 圆角 | 3 档：6 / 10 / 16 | 21 种圆角 |
| 字号 | 7 档：11/12/13/15/18/24/32 | 19 种字号且分布倒挂 |
| 节奏 | 所有间距来自 `--space-1..7` | 随手写 7px / 9px / 13px |
| 动效 | 只用于状态变化，120–180ms | 装饰性动画 |

## 4. 与现状的关系

**这是收敛，不是推翻重做。** 主色 `#1f7667` 不是新选的——它是现有 `main.css` 三个 `:root` 块里**最后生效**的 `--accent-strong` 值。迁移到这套 token 后，界面的**调性不变、噪音大幅减少**。

改完之后应该出现的感受是："**好像没换，但清楚多了**"，而不是"又换了一套配色"。

如果改完你觉得"变了个样"，说明方向错了，回来看这一节。
