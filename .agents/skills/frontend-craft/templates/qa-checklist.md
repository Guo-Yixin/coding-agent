# qa-checklist.md — 视觉验收清单

> **用法**：截图 → 对着这张清单逐条回答 → 发现问题 → 改 → 再截图。
> 每条都必须能用"看截图"回答。答不上来的条目说明截图拍得不对，不是清单有问题。
>
> 检查顺序**不能变**。前 3 组是结构问题，结构不对时调颜色毫无意义 ——
> 在第 1 组就失败的情况下修第 5 组，是纯粹的浪费时间。

---

## 0. 截图准备（先做这个，否则后面全是猜）

- [ ] 截了**正常态**（有数据）
- [ ] 截了**空态**（无数据）—— 新用户看到的就是这个
- [ ] 截了**加载态**（pending / 骨架屏）
- [ ] 截了**错误态**（请求失败）
- [ ] 截了**超长内容**（长标题、长列表、长 URL 不溢出）
- [ ] 截了**窄宽度**（375px）和**常规宽度**（1280px+）
- [ ] 截图能看清细节（≥1x 缩放，不是缩略图）
- [ ] 截图时**隐藏了滚动条与光标**，避免干扰判断

> 截图命令：`node scripts/capture.mjs <url-or-file> shots --widths 375,1280`
> 没有截图就等于没有验收。**"我觉得应该没问题"不是验收。**

---

## 1. 对齐与栅格（最优先 —— 错了后面都白搭）

- [ ] 页面上**所有元素**的左边缘，只落在**少数几条垂直线**上？（2~4 条）
- [ ] 相邻区块的间距，看起来是**同一个值**吗？（不是"差不多"）
- [ ] 侧栏/内容/页边距的边界在整个页面上下**一致**吗？
- [ ] 有没有元素比同级元素**多缩进或少缩进** 2~6px？（这是最常见的肉眼可辨错位）
- [ ] 卡片内部的 padding，和卡片之间的 gap，数值是**同一套**吗？
- [ ] 图标和它旁边的文字**垂直居中对齐**吗？
- [ ] 表单的 label 和它的输入框左边缘对齐吗？

> **判据**：闭上眼睛再睁开，视线扫过页面 —— 有没有哪里"跳"一下？
> 有就是对齐问题，不是颜色问题。

---

## 2. 层级与灰度（信息层级是否可读）

- [ ] 文字灰度**不超过 4 档**？（数一下：正文 / 次级 / 弱化 / 强调）
- [ ] 有没有两种灰**肉眼几乎分不出**却同时存在？（#6b6b6b 和 #6b7780 这种）
- [ ] 页面看起来会不会**"发脏"**？发脏通常是两套灰色混用。
- [ ] 标题和正文字号的差距，是**一眼能看出层级**的吗？
- [ ] 有没有 10px 以下的文字？没有内容重要到需要 8px 才能表达。
- [ ] 次级信息（说明、时间戳、元数据）是不是**真的比正文弱**，
      而不只是"小一号"？

> **判据**：眯起眼睛看截图（或把截图缩小到 25%）。
> 层级还在吗？还在 = 层级是对的；糊成一片 = 只有字号差别，没有视觉层级。

---

## 3. 控件一致性（"看起来专业"的核心）

- [ ] 同一行里的按钮/输入框/下拉框，**高度完全相同**吗？（逐个量）
- [ ] 所有同类控件的**圆角**是同一个值吗？
- [ ] 所有输入框（input/textarea/select）的**边框色和内边距**一致吗？
- [ ] 代表同一级操作的按钮，用的是**同一个 variant** 吗？
- [ ] 主操作按钮在页面上是否**唯一且显眼**？
- [ ] 按钮里的文字和图标之间的间距一致吗？
- [ ] 有没有两个控件视觉重量相同、但语义层级不同？（会让人不知道点哪个）

> **判据**：把所有按钮裁下来排成一行，它们看起来像**同一个设计系统的产物**吗？
> 有一个不像，就是它的问题。

---

## 4. 间隔节奏

- [ ] 所有间距都来自 `--space-*` 这套值吗？（数一下有几个不同的间距值）
- [ ] 不同间距值的总数**≤7** 吗？
- [ ] 相关元素之间的间距，**小于**不相关元素之间的间距吗？
      （接近性原则 —— 反了会让分组关系读错）
- [ ] 区块之间的留白，会不会某一个特别大、显得像漏了内容？
- [ ] 页面顶部的留白和底部的留白，量级是否合理？

---

## 5. 颜色

- [ ] 有彩色（非灰）总数**≤4** 吗？（主色 + success + warning + danger）
- [ ] 主色在全页只出现**一处**作为品牌识别，而不是三四个地方各一个绿吗？
- [ ] 有没有**孤立的颜色**（只用了一次、来历不明）？
- [ ] 语义色用得对吗？成功的事是绿的，危险的事是红的？
- [ ] 浅色底上的深色文字，和深色底上的浅色文字，**对比度都够**吗？
- [ ] 有没有用颜色**单独**传达信息？（色盲用户看不到 —— 需要配图标或文字）

> 对比度速查（WCAG AA，正文 4.5:1）：
> `#1c2321` on `#ffffff` ≈ 14.9:1 ✓ ｜ `#5a6561` on `#ffffff` ≈ 6.4:1 ✓
> `#8a938f` on `#ffffff` ≈ 3.2:1 ✗ **不要用它写正文**，只用于弱化标注
> 校验工具：浏览器 DevTools 的对比度提示，或任意 contrast checker。

---

## 6. 交互状态（对照检查，不是看截图就能发现的）

- [ ] 每个可点击元素的 **hover** 态有变化吗？
- [ ] 用 Tab 键走一遍：**每一个**可聚焦元素都有可见焦点环吗？
- [ ] 有没有 `outline: none` 而没有替代焦点样式？
- [ ] 禁用态和可用态**一眼可分**吗？
- [ ] 加载中时，可点击元素是否被禁用（防重复提交）？
- [ ] 操作成功/失败后有反馈吗（toast / 内联错误）？

---

## 7. 文本健壮性

- [ ] 把标题换成 3 倍长度的文字，布局会**崩**吗？
- [ ] 长英文单词/URL 会溢出容器吗？（需要 `overflow-wrap: anywhere`）
- [ ] 长列表滚动时，表头/工具栏是否保持可用（sticky）？
- [ ] 数字列是等宽对齐的吗？（否则列表看起来参差）
- [ ] 中文和英文混排时，间距看起来自然吗？

---

## 8. 和参照物对比（最后一关，也是最能提升的一关）

- [ ] 把截图和 `docs/design/reference/` 里的参照图**并排**打开
- [ ] 列出 **3 个具体差距**（不是"感觉不如它好看"，而是"它的列表行高更大"这种）
- [ ] 这 3 个差距里，有没有属于前面 1~7 组已经检查过的？
      （有 → 前面的检查漏了，回去补）
- [ ] 剩下的差距里，挑**一个**改，再截图对比。

> **不要一次改三个差距。** 一次一个，改完对比，确认变好了再下一个。
> 同时改多个 = 无法归因 = 明天又漂回去。

---

## 验收失败怎么办

| 失败组 | 优先修什么 | 不要做什么 |
|---|---|---|
| 1 对齐 | 统一间距值和左边缘 | 不要先调颜色 |
| 2 灰度 | 删掉多余的灰，收敛到 4 档 | 不要加新颜色来"区分" |
| 3 控件 | 统一高度和圆角 | 不要给单个控件做特例 |
| 4 间隔 | 归到 `--space-*` | 不要手工试数值 |
| 5 颜色 | 删掉孤立色 | 不要保留"因为这个页面特殊" |
| 6 状态 | 补全 hover/focus/disabled | 不要用 `!important` 压 |
| 7 文本 | 加 `overflow-wrap` / `min-width: 0` | 不要写死宽度 |
| 8 参照 | 一次改一个差距 | 不要同时改三个 |

**任何一次修完，回到第 0 步重新截图。** 没有重新截图 = 没有修完。
